### Аудит численного прогноза

Независимый запуск `open_data_predictor.py` воспроизводит JSON без расхождений.
Код загружает ровно 20 строк полной сетки 5 x 4, использует признаки
`[1, nr, cb, nr*cb, nr^2, cb^2]`, ridge `1e-6`, честный LOOCV с повторным fit на
19 строках и перебор целых NR 25-75, N220 20-80 phr. Кандидат NR 58 / N220 60
находится внутри опубликованного домена; нормированная дистанция до ближайшей
наблюдаемой точки - 0.32.

| Свойство | Прогноз | Ограничение | LOOCV RMSE | Точечно | С учётом +/-RMSE |
|---|---:|---:|---:|---|---|
| Теплопроводность, W/(m*K) | 0.45186 | >= 0.45 | 0.02142 | Да | Нет |
| Набухание в масле, % | 19.78792 | <= 20 | 2.56418 | Да | Нет |
| Набухание в воде, % | 27.86010 | <= 28 | 1.57623 | Да | Нет |
| Удельный вес | 1.20970 | <= 1.23 | 0.00876 | Да | Да |

Вердикт: прогнозы численно и кодово согласованы, но `constraints_satisfied`
означает только выполнение по точечным оценкам. При консервативной проверке
`+/-1 LOOCV RMSE` робастно подтверждён только удельный вес.

Основные риски: вручную оцифрованные графики вместо первичных измерений; всего 20
точек; выбор кандидата той же моделью и на тех же данных; отсутствие внешней и
лабораторной валидации. До практических выводов нужны независимые измерения.
