# FEDOT.MAS GUI

Веб-интерфейс для генерации и запуска мультиагентных систем. Показывает граф
агентов, вызовы инструментов и итоговый ответ. Позволяет сравнить результат
с ответом одной модели, оценить его моделью-судьёй и сохранить сценарий.
Интерфейс на русском языке.

## Запуск

Нужны Python 3.12+, `uv` и `just`. Из корня репозитория:

```bash
uv sync
uv pip install -r gui/requirements.txt
just mcp-sync
uv run python gui/run.py
```

Откройте <http://localhost:4173>. В окне «Выбор модели» нажмите
«Ввести ключ OpenRouter», вставьте ключ и выберите «Проверить и продолжить».
Проверка ключа и последующие запуски обращаются к провайдеру моделей.

Для локального запуска ключ также можно задать в `.env` в корне репозитория:

```dotenv
OPENROUTER_API_KEY=sk-or-...
```

Если ключ уже задан на сервере, кнопка ввода скрыта. Флажок «Запомнить в этом
браузере» сохраняет введённый ключ в браузере; сервер использует его в памяти
процесса и не записывает в `.env`.

Локально доступны и модели через авторизованный Codex CLI. Это дополнительный
вариант подключения; для запуска через OpenRouter Codex не требуется.

## Работа со сценарием

1. Выберите готовый сценарий или нажмите «Добавить сценарий» и опишите задачу.
2. Выберите модели и инструменты, сгенерируйте систему и проверьте конфигурацию.
3. Нажмите «Запустить». Результат и журнал выполнения появятся рядом с графом.
4. При необходимости используйте «Сравнить с одной моделью» или «Оценить судьёй».
   «Проверочные варианты» создают новые входные запросы для той же системы.

Сценарий можно выгрузить в JSON и открыть кнопкой «Импортировать».
Файл содержит конфигурацию, ответы и журнал; сохранённые результаты доступны
без повторного запуска. Перед передачей файла проверьте его содержимое:
в него входят данные задачи и сведения из источников, прочитанных агентами.

В комплекте есть [запись контрольного расчёта свойств резины](recordings/README.md).
MAPE 3,21 % относится к одной рецептуре, исключённой из обучения, и четырём
свойствам. Это ретроспективная проверка по опубликованным данным.

## Инструменты и источники

Доступные инструменты показаны в окне сценария. Проверить окружение MCP-серверов:

```bash
just doctor
```

Для веб-поиска и чтения веб-страниц можно дополнительно установить SearXNG
(требуется Docker) и Lightpanda:

```bash
just searxng-start
just lightpanda-install
```

После установки перезапустите GUI. Дополнительные локальные серверы задаются
через `GUI_EXTRA_TOOLS`. Свой MCP-сервер можно подключить по URL; для подключения
через реестр Smithery GUI использует `SMITHERY_API_KEY`.
Настройка серверов описана в [документации MCP](../mcp-servers/README.md).

К задаче можно добавить ссылки и файлы. Для их обработки нужны инструменты
`download` и `document`. Размер загружаемого файла по умолчанию ограничен 25 МБ.
В публичном режиме эти инструменты и загрузка файлов по умолчанию отключены.

## Доступ по внешней ссылке

GUI предназначен для демонстраций доверенным пользователям. Обладатель ссылки
может запускать агентов и доступные им инструменты на сервере.

После локальной настройки выполните:

```bash
./gui/serve-public.sh
```

Скрипт требует `zsh` и SSH-клиент, запускает публичный режим на порту `4174`
и создаёт туннель через Pinggy. Порт должен быть свободен: если он занят,
скрипт использует уже работающий сервер. Откройте напечатанную ссылку целиком,
включая токен доступа. Для остановки используйте `Ctrl+C`.

В публичном режиме:

- Ключ OpenRouter вводится через интерфейс; серверные ключи провайдера из `.env`
  не используются. Введённый ключ общий для процесса: все посетители работают
  с текущим ключом, поэтому используйте стенд по одному пользователю за раз.
- Модели локального Codex недоступны.
- Чтение и запись файлов хоста через `document` и `download` по умолчанию отключены.

Токен ограничивает доступ к стенду, но не изолирует выполнение агентов.
При выборе туннеля учитывайте, что его оператор может иметь доступ к передаваемым
ключам и данным. Для постоянного многопользовательского сервиса нужны отдельные
учётные записи, изоляция выполнения и управление ключами.

## Решение проблем

| Проблема | Что проверить |
|---|---|
| Интерфейс не подключается к серверу | Вывод `gui/run.py`, установку зависимостей и порт `GUI_PORT` (по умолчанию `4173`) |
| «Не задан ключ провайдера» (HTTP 428) | Для моделей OpenRouter задайте `OPENROUTER_API_KEY` или введите ключ в интерфейсе; в публичном режиме используйте ввод в интерфейсе |
| «Нет доступа» (HTTP 401) | Откройте полную ссылку с токеном или введите код доступа из вывода скрипта |
| Нужного инструмента нет или он не запускается | Выполните `just doctor`, проверьте зависимости сервера и перезапустите GUI |

## Для разработчиков

Запуск тестов из корня репозитория (для JavaScript нужен Node.js):

```bash
uv sync --group dev
uv run pytest gui/tests/ -q
node --test gui/tests/test_*.js
```

Сборка автономной HTML-копии с сохранёнными сценариями:

```bash
uv run python gui/tools/build_offline.py
```

Файл `gui/fedotmas-offline.html` открывается без сервера и показывает записанные
результаты. Новые запросы к моделям в этой копии не выполняются.
