# FEDOT.MAS GUI — веб-стенд для демонстрации

Интерфейс, который по тексту задачи собирает мультиагентную систему через FEDOT.MAS,
исполняет её и показывает работу вживую: граф агентов, ленту выполнения, вызовы
инструментов, итоговый ответ. Рядом — сравнение с одной моделью и независимый судья.

Фронтенд без сборки: HTML, CSS и ванильный JS. Бэкенд — FastAPI, который импортирует
FEDOT.MAS как библиотеку и гоняет её в своём процессе.

## Быстрый старт

Из корня репозитория FEDOT.MAS один раз собрать окружение и MCP-серверы:

```bash
uv sync
uv pip install -r gui/requirements.txt
for d in mcp-servers/*/; do env -u UV_PROJECT_ENVIRONMENT -u VIRTUAL_ENV uv sync --directory "$d"; done
```

Авторизовать Codex CLI в той же учётной записи, где активна подписка Codex:

```bash
codex login
codex login status
```

Модели `host/gpt-5.6-terra`, `host/gpt-5.6-sol` и `host/gpt-5.6-luna`
вызываются через локальный `codex exec`. Это transport подписки Codex, а не
OpenAI-совместимый API; `OPENAI_API_KEY` для них не нужен.

Запустить:

```bash
uv run python gui/run.py
```

Открыть <http://localhost:4173>. Два стартовых сценария показывают MAS для
предсказания свойств заданного рецепта резины и для аудита норм технологической
карты; новый сценарий можно собрать кнопкой «Добавить сценарий».

Первый запуск занимает больше времени: поднимаются MCP-серверы (`uv` доставляет их
окружения). Дальше они стартуют за секунды.

## Внешний доступ

Стенд слушает только `127.0.0.1` и наружу сам не смотрит. Чтобы коллеги открыли его
со своей машины, есть готовый скрипт — он поднимает сервер в **публичном режиме** и
пробрасывает туннель:

```bash
./gui/serve-public.sh
```

Скрипт поднимает стенд на порту **4174**, а не 4173: локальный стенд при этом можно
не гасить. Он печатает ссылку с токеном доступа и повторяет её, если туннель
переподключился и адрес сменился. Провайдер туннеля выбирается переменной:

| Значение | Провайдер | Чем плох |
|---|---|---|
| `pinggy` (по умолчанию) | pinggy.io | бесплатная сессия ~60 минут, страница-предупреждение при первом заходе |
| `lhr` | localhost.run | меняет адрес прямо посреди сессии |
| `serveo` | serveo.net | **рвёт запросы длиннее ~6 секунд** — не использовать |

```bash
TUNNEL=lhr ./gui/serve-public.sh
```

Цифры в таблице — замеры на этом стенде, а не обещания провайдеров. Постоянного
бесплатного адреса среди них нет ни у кого: pinggy обрывает сессию через час,
localhost.run меняет имя на живом соединении. Cloudflare Tunnel даёт постоянный
адрес и аутентификацию Zero Trust бесплатно — если в сети не режут порт 7844.

### Что меняется в публичном режиме

`GUI_PUBLIC=1` включает два заслона, и они закрывают разные дыры.

**Ключ провайдера вводит пользователь.** Сервер первым делом выкидывает
`OPENAI_API_KEY` из своего окружения — до того, как его успеет прочитать FEDOT.MAS.
Ключ приходит из интерфейса, проверяется живым запросом, нигде не сохраняется на
диск и пишется в журнал замаскированным (`sk-or-…0d67`). Живёт он в окружении
процесса — оттуда его читают и FEDOT.MAS, и подпроцессы MCP-серверов, которым он
нужен (например, `media`). Так владелец стенда не платит за чужие запуски.

Важно: ключ **один на процесс**, а не на посетителя. Кто ввёл его первым — за того
и платят все остальные, и любой следующий может подменить ключ своим. Стенд
демонстрационный и рассчитан на одного человека за раз.

**Токен доступа.** Ключ решает вопрос денег, но не вопрос песочницы: `/api/run`
исполняет код на машине. Поэтому все `/api/` требуют заголовок `X-Access-Token`;
исключение одно — `/api/status`, иначе страница не смогла бы показать форму входа.
Токен генерируется при старте, вшивается в ссылку (`?t=…`), интерфейс кладёт его в
`localStorage` и стирает из адресной строки, чтобы он не попал в скриншот. Модель
ровно как у Jupyter: ссылка и есть пропуск.

Если ссылка пришла без токена (например, его срезала страница-предупреждение
туннеля), в форме входа появится поле «Код доступа» — его печатает тот же скрипт.

Экспорт сценариев в файл наружу закрыт совсем: `/api/export-presets` отдаёт 403
даже с верным токеном, потому что пишет на диск рядом с кодом.

Инструменты `document` и `download` в публичном режиме не выдаются агентам:
первый читает любой файл по абсолютному пути, второй пишет файл в любой каталог,
а агент делает то, о чём попросил гость. Ссылка означала бы доступ к `~/.ssh` и к
записи в автозагрузку. Включить их для доверенной аудитории — `GUI_PUBLIC_ALLOW_FS=1`.

Локальный режим не меняется ни в чём: без `GUI_PUBLIC` ключ берётся из `.env`,
токен не нужен.

### Чего эта защита не делает

Честно о границах, чтобы не было ложного спокойствия.

**Туннель видит трафик.** pinggy, localhost.run и serveo терминируют TLS у себя.
Это значит, что провайдер туннеля видит в открытом виде тело запроса `/api/key` —
то есть боевой ключ OpenRouter, — заголовок с токеном доступа и все ответы моделей.
Токен вдобавок попадает в их журналы вместе с адресом. Раздавайте ссылку на время
показа и гасите стенд после; для постоянного доступа нужен свой домен и туннель,
которому вы доверяете.

**Стенд не рассчитан на открытый интернет.** Токен закрывает случайного прохожего,
но любой, кому вы дали ссылку, запускает агентов на вашей машине: песочница
исполняет код, веб-инструменты ходят в сеть с вашего адреса, свой MCP-сервер по
ссылке — это запрос от вашей машины на указанный адрес. Круг получателей ссылки и
есть круг доверия.

**Ключ один на всех.** См. выше: второй посетитель платит с чужого баланса.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `OPENAI_API_KEY`, `OPENAI_BASE_URL` | из `.env` | доступ к провайдеру моделей |
| `GUI_PORT` | `4173` | порт стенда |
| `GUI_HOST` | `127.0.0.1` | адрес прослушивания; для прокси среды разработки можно задать `0.0.0.0` |
| `GUI_PUBLIC` | выкл. | публичный режим: токен доступа + ключ от пользователя |
| `GUI_ACCESS_TOKEN` | случайный | зафиксировать токен, чтобы ссылка пережила перезапуск |
| `GUI_PUBLIC_ALLOW_FS` | выкл. | вернуть наружу `document` и `download` (чтение и запись файлов хоста) |
| `GUI_UPLOAD_MAX_MB` | `25` | предел размера файла-источника |
| `SMITHERY_API_KEY` | пусто | ключ реестра MCP: без него найденные серверы не подключаются |
| `GUI_ALLOWED_HOSTS` | пусто | дополнительные имена хоста, с которых принимать запросы |
| `GUI_MODEL` | `host/gpt-5.6-terra` | модель Codex по умолчанию |
| `GUI_JUDGE_MODEL` | `host/gpt-5.6-terra` | модель судьи |
| `GUI_EXTRA_TOOLS` | `rubber-recipe-predictor,technology-card-audit` | список дополнительных инструментов; можно добавить `browser-usage,youtube-transcript` |
| `SEARXNG_URL` | `http://localhost:18888` | адрес своего SearXNG |
| `GUI_SSE_HEARTBEAT` | `10` | период пульса в потоке событий, секунды |
| `GUI_AGENT_MAX_OUTPUT_TOKENS` | `12000` | лимит вывода агента |
| `GUI_GENERATE_ATTEMPTS` | `3` | сколько раз повторить генерацию при невалидной схеме |
| `GUI_JUDGE_FALLBACK` | `host/gpt-5.6-terra` | запасная модель судьи |
| `GUI_JUDGE_MAX_TOKENS` | `16000` | лимит вывода судьи |
| `GUI_JUDGE_RETRY_TIMEOUT` | `90` | сколько ждать строгий повтор судьи, секунды |
| `E2B_API_KEY` | пусто | добавляет полную песочницу `sandbox` рядом с `sandbox-light` |

Переменные вспомогательных скриптов: `GUI_BASE` — адрес стенда для `preflight.py`;
`TUNNEL`, `SERVEO_SUBDOMAIN`, `LHR_KEY`, `LHR_USER`, `PYTHON` — для `serve-public.sh`.

## Инструменты агентов

Инструменты, которым нужно внешнее окружение, сервер проверяет при старте и не
предлагает мета-агенту, если проверка не прошла: иначе агент получает инструмент,
который падает на первом же вызове. Проверяются два — SearXNG и Lightpanda.
Остальные локальные включаются безусловно, `sandbox` — по наличию `E2B_API_KEY`,
а всё из `GUI_EXTRA_TOOLS` добавляется без проверок.

| Инструмент | Что делает | Требования |
|---|---|---|
| `sandbox-light` | быстрые расчёты на чистом Python | нет |
| `sandbox` | полная песочница: pip, файлы, shell | `E2B_API_KEY` |
| `sequential-thinking` | пошаговый разбор рассуждений | нет |
| `document` | чтение PDF, DOCX, XLSX, CSV, архивов | нет |
| `download` | скачивание файлов по ссылке | нет |
| `media` | разбор изображений, аудио, видео | ключ провайдера |
| `websearch-searxng` | веб-поиск | поднятый SearXNG |
| `web-scraping` | открыть страницу и вытащить содержимое | браузер Lightpanda |

Веб-поиск и браузер — необязательные. Без них стенд работает, просто эти инструменты
не предлагаются:

```bash
just searxng-start          # веб-поиск, контейнер на порту 18888
just lightpanda-install     # браузер для web-scraping, ставится в ~/.local/bin
```

Кроме встроенных серверов в окне сценария можно подключить любой MCP из реестра
[Smithery](https://registry.smithery.ai) (около 12 тысяч записей) или свой по ссылке.
Поиск по реестру англоязычный: `geocoding` находит Mapbox и OpenStreetMap,
«геокодирование» — ничего.

**Искать в реестре можно без ключа, а подключаться — нет.** Проверено запросом: все
развёрнутые серверы Smithery отвечают `401 Missing Authorization header`. Заведите
ключ на [smithery.ai](https://smithery.ai) и задайте `SMITHERY_API_KEY` — сервер
подставит его сам, в браузер ключ не уходит. Без ключа интерфейс покажет найденное,
но честно предупредит, что подключение не заработает.

## Источники данных: ссылки и файлы

В окне сценария у источников две графы. **Ссылки** агент скачивает сам через
`download`. **Файлы** — таблица, выписка, отчёт с компьютера — загружаются на стенд,
а путь к ним дописывается в запрос; читает их тот же инструмент `document`, что и
скачанные. Одновременно можно и то, и другое.

Проверено прогоном: в задаче «прочитай приложенный файл и посчитай прибыль» система
взяла числа из CSV, которых не было в тексте задачи. Файлы кладутся во временный
каталог, предел размера — `GUI_UPLOAD_MAX_MB`. В публичном режиме прикрепление
недоступно: там отключён `document`, без которого файл прочитать нечем.

## Перенос сценария между машинами

Сценарий целиком — схема системы, журнал прогона, ответ, ответ одной модели, вердикт
судьи, разбор трудоёмкости и источники — выгружается в JSON кнопкой со стрелкой
справа от полосы прогресса. Кнопка «Импортировать» рядом с «Добавить сценарий»
загружает такой файл обратно. Открыть импортированный сценарий можно без ключа и без
запуска: всё нужное лежит в файле.

## Структура

```
gui/
├── run.py                точка входа: python gui/run.py
├── serve-public.sh       внешний доступ: публичный режим + туннель
├── requirements.txt      зависимости стенда поверх FEDOT.MAS
├── server/               бэкенд
│   ├── app.py            маршруты API и раздача статики
│   ├── config.py         настройки, модели, список инструментов
│   ├── security.py       токен доступа и ключ провайдера
│   ├── schemas.py        схемы запросов
│   ├── prompts.py        тексты, которые уходят моделям
│   ├── normalize.py      правка конфигурации от мета-агента
│   ├── agent_names.py    латинские имена агентов MAS на время запуска
│   ├── judge.py          сравнение ответов
│   ├── streaming.py      плагин событий ADK и обёртка SSE
│   ├── infra.py          проверки SearXNG и Lightpanda
│   └── llm.py            прямой клиент провайдера
├── static/               интерфейс: index.html, app.js, styles.css, presets.js
├── tools/                preflight, check_presets, record_run, build_offline, mock_backend
├── example_config.json   пример MAWConfig от мета-агента
└── .gitignore            токен доступа, ключи, сборки и журналы
```

### Почему конфигурацию приходится править

`server/normalize.py` — не украшательство, а набор заплат от конкретных сбоев.
Главный вывод за время подготовки: **инструкции агентам работают ненадёжно**, модель
их регулярно игнорирует, и всё, что обязано выполняться, приходится закреплять
структурно. Например, мета-агент ставил агента-планировщика в одну параллельную
ветку с агентом, чьи результаты планировщику и нужны: тот стартовал одновременно,
получал пустой вход и писал план вслепую. Каждая функция в модуле объясняет, какой
именно сбой она чинит.

### Почему у агентов MAS в журнале латинские имена

Мета-агента просят называть агентов по-русски: имена видны на экране, и по ним
`normalize.py` узнаёт роли (критик, сборщик). Но в MAS исполнитель становится у
координатора инструментом с именем агента, а OpenAI принимает в имени инструмента только
латиницу — кириллица роняла первый же ход координатора (`400 Invalid 'tools[3].name'`).
Поэтому сценарий хранит русские имена, а запуск идёт под транслитерированными
(`server/agent_names.py`): граф, лента, итог и сохранённый сценарий показывают исходные
имена, латинские остаются только в журнале сервера. MAW это не касается — там агенты
инструментами не становятся.

## Как это устроено

| Эндпоинт | Что делает |
|---|---|
| `GET /api/status` | режим, модели, доступные инструменты и MCP-серверы |
| `POST /api/key` | принять и проверить ключ провайдера (публичный режим) |
| `POST /api/generate_stream` | мета-агент проектирует систему, события идут потоком |
| `POST /api/run` | система исполняется, события идут потоком |
| `POST /api/baseline` | та же задача одной моделью, без системы |
| `POST /api/judge_stream` | независимый судья сравнивает оба ответа |
| `POST /api/effort_breakdown` | разбор задачи на подзадачи с оценкой в часах |
| `GET /api/mcp_search` | поиск MCP-серверов в реестре Smithery |
| `GET /api/mcp_catalog` | встроенные MCP-серверы и их доступность |
| `POST /api/prepare` | разделить текст на постановку для мета-агента и запрос |
| `POST /api/generate`, `POST /api/judge` | то же, что потоковые версии, но одним ответом |
| `POST /api/effort` | общая оценка трудоёмкости без разбора на подзадачи |
| `POST /api/export-presets` | сохранить сценарии в файл (только локально) |
| `POST /api/upload` | принять файл-источник и вернуть путь для агента |

События потока: `agent_start`, `agent_done`, `tool`, `tool_result`, `text`, `tokens`,
`done`, `error`. Раз в `GUI_SSE_HEARTBEAT` секунд уходит строка-пульс `: ping` —
без неё туннели и обратные прокси рвут молчащее соединение, а судья между событиями
молчит по минуте.

## Вспомогательные скрипты

```bash
python gui/tools/preflight.py          # проверка окружения перед показом
python gui/tools/check_presets.py      # проверка сценариев по правилам моделей fedotmas
python gui/tools/record_run.py --help  # запись живого прогона в сценарий
python gui/tools/build_offline.py      # автономная HTML-копия с записанными прогонами
```

Автономная копия открывается двойным кликом на любой машине и показывает интерфейс с
записанными прогонами из `static/presets.js`. По-настоящему она ничего не исполняет —
FEDOT.MAS живёт в Python, а не в браузере; на странице это помечено плашкой.

Что уходит в выгруженный сценарий, стоит знать до пересылки: там полные входы и
выходы агентов, а если источником был файл — путь к нему на вашей машине и всё, что
агент из него прочитал.

## Если что-то не работает

**Кнопки заблокированы, сверху нет моделей.** Бэкенд не отвечает: посмотрите вывод
`run.py`. Чаще всего не установлены зависимости из `requirements.txt`.

**`не задан ключ провайдера` (HTTP 428).** В локальном режиме — нет `.env` или в нём
нет `OPENAI_API_KEY`. В публичном — ключ ещё не введён в интерфейсе.

**`нет доступа` (HTTP 401).** Публичный режим, ссылка открыта без токена. Возьмите
ссылку целиком из вывода `serve-public.sh` или введите код в форме.

**Веб-поиска нет среди инструментов.** SearXNG не поднят — `just searxng-start`.
Стенд при этом работает, агентам просто не выдаётся поиск.

**Генерация падает с `Unknown MCP server`.** Конфигурация ссылается на инструмент,
которого нет на машине. Сервер такие ссылки вычищает сам; если сообщение всё же
появилось — пришлите конфигурацию из вкладки JSON.
